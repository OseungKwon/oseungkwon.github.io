처음에는 함수 하나로 충분했던 기능이 요구사항이 붙을 때마다 커져, 작은 수정에도 여러 조건을 확인하느라 시간을 많이 쓴 경험이 있으신가요?

이 글의 예시는 5천 원 할인 쿠폰 하나로 시작하는 쿠폰함입니다. 백엔드에서 받은 쿠폰의 사용 여부를 확인하고, 진행 중인 주문의 상품 금액에서 5천 원을 빼면 됩니다. 10% 할인 쿠폰과 배송비 쿠폰이 생기고 사용 기간도 쿠폰마다 달라지면, 클릭 함수에 붙인 조건이 쿠폰함 목록과 상품 카드에도 필요해집니다.

쿠폰함은 사용 가능 여부와 예상 할인액을 보여주고, 선택한 쿠폰을 백엔드에 적용해 달라고 요청합니다. 이후 상품 카드에도 보유 쿠폰을 적용한 최저가를 표시해야 합니다. 이 가상의 기능에 로버트 C. 마틴의 『클린 아키텍처』 16장 「독립성」과 20장 「업무 규칙」의 구분을 적용해 보겠습니다.

## 한 함수에 쌓이는 쿠폰 조건과 API 요청

초기 화면에서는 쿠폰을 누르면 목록과 주문을 가져와 사용 가능 여부를 확인하고, 백엔드에 적용을 요청합니다. 쿠폰은 모두 발급 후 30일 동안 유효하고 할인액은 5천 원으로 고정되어 있습니다.

```ts
type LegacyCouponDto = {
  id: string;
  issuedAt: string;
  usedAt: string | null;
};

const DAY = 24 * 60 * 60 * 1000;

async function handleCouponClick(couponId: string) {
  const [couponsResponse, orderResponse] = await Promise.all([
    fetch('/api/me/coupons'),
    fetch('/api/orders/current'),
  ]);
  if (!couponsResponse.ok || !orderResponse.ok) {
    throw new Error('쿠폰 정보를 불러오지 못했습니다.');
  }

  const coupons = await couponsResponse.json();
  const order = await orderResponse.json();
  const coupon = coupons.find((item: LegacyCouponDto) => item.id === couponId);

  // 모든 쿠폰에 '발급 후 30일'이라는 같은 만료 조건을 적용합니다.
  if (
    !coupon ||
    coupon.usedAt ||
    Date.now() >= Date.parse(coupon.issuedAt) + 30 * DAY
  ) {
    setMessage('사용할 수 없는 쿠폰입니다.');
    return;
  }

  // 할인액이 상품 금액을 넘지 않도록 제한합니다.
  const expectedDiscount = Math.min(5000, order.productTotal);
  setExpectedDiscount(expectedDiscount);

  const response = await fetch(`/api/orders/${order.id}/coupon`, {
    method: 'PUT',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({ couponId }),
  });
  if (!response.ok) {
    setMessage('쿠폰을 적용하지 못했습니다.');
    return;
  }

  setQuote(await response.json());
}
```

쿠폰함 목록에 사용 가능 표시를 붙이면 같은 만료 조건을 목록 변환 함수에도 적게 됩니다.

```ts
function toCouponListItem(coupon: LegacyCouponDto) {
  // 클릭 함수와 같은 '발급 후 30일' 조건을 다시 사용합니다.
  const expiresAt = Date.parse(coupon.issuedAt) + 30 * DAY;

  return {
    id: coupon.id,
    available: coupon.usedAt === null && Date.now() < expiresAt,
  };
}
```

3만 원짜리 주문에 5천 원 할인 쿠폰을 쓰면 5천 원이 할인됩니다. 같은 주문에 10% 할인 쿠폰을 쓰면 계산값은 3천 원이지만, 최대 할인액이 2천 원이라면 2천 원만 할인해야 합니다. 기존 `expectedDiscount`는 쿠폰 종류와 할인 한도를 알지 못하므로 계산 분기를 추가해야 합니다. 쿠폰함 목록에도 예상 할인액을 보여준다면 같은 분기가 목록을 만드는 코드에도 들어갑니다.

만료일을 쿠폰마다 다르게 지정하는 요구사항은 또 다른 불일치를 만듭니다. 9월 1일에 발급됐지만 9월 15일에 끝나는 쿠폰을 생각해 보겠습니다. 클릭 함수만 새 `expiresAt`을 검사하고 목록에는 `issuedAt + 30 * DAY`를 남겨두면, **9월 20일에도 쿠폰함은 이 쿠폰을 사용 가능으로 표시합니다**. 고객이 누르고 나서야 만료됐다는 메시지를 보게 됩니다.

할인액과 만료일은 쿠폰함의 어느 화면에서 확인하든 같은 값이어야 합니다. 지금은 그 판단이 화면 상태 변경과 API 요청 사이에 들어 있어, 요구사항을 바꿀 때 조건이 적힌 곳을 함께 찾아야 합니다. 쿠폰을 사용할 수 있는지와 얼마를 할인하는지를 결정하는 코드가 이 글에서 다룰 쿠폰의 업무 규칙입니다.

> **엔티티(Entity)**  
> 쿠폰의 사용 기간과 할인 혜택을 가지고 “지금 쓸 수 있는가”, “이 주문에서 얼마를 할인하는가”에 답하는 모델입니다. 쿠폰함에서 보든 상품 카드에서 보든 같은 답을 내야 하는 판단이 여기에 들어갑니다. 데이터베이스의 쿠폰 행이나 API 응답을 그대로 옮긴다는 뜻은 아닙니다.

> **유스케이스(Use Case)**  
> 사용자가 하려는 한 가지 일을 완성하는 흐름입니다. “쿠폰함 보기”라면 고객의 쿠폰과 현재 주문을 가져와 각 쿠폰의 상태와 예상 할인액을 화면에 돌려줍니다. 함수 호출 순서뿐 아니라 어떤 데이터를 모으고, 어떤 쿠폰 규칙을 사용해, 무엇을 반환할지도 정합니다.

쿠폰함은 고객의 쿠폰과 현재 주문을 가져오고, 상품 카드는 상품 가격과 보유 쿠폰을 가져옵니다. 가져오는 데이터는 달라도 쿠폰이 만료됐는지 판단하는 코드는 같습니다. API 주소와 응답 파싱은 데이터를 가져오는 쪽에만 남깁니다.

## 쿠폰 상태와 할인액을 엔티티에 두기

5천 원 할인 쿠폰에는 할인 금액이, 10% 할인 쿠폰에는 할인율과 최대 할인액이 필요합니다. 이 값을 모두 선택 속성으로 두면 `rate`가 없는 10% 할인 쿠폰도 타입 검사를 통과합니다. 쿠폰 종류별로 필요한 값을 나눕니다.

```ts
type CouponBenefit =
  | { type: 'amount'; amount: number }
  | { type: 'percent'; rate: number; maxDiscount: number }
  | { type: 'shipping' };

type Coupon = {
  id: string;
  validFrom: number;
  expiresAt: number;
  usedAt: number | null;
  minimumProductTotal: number;
  benefit: CouponBenefit;
};

type DiscountContext = {
  productTotal: number;
  shippingFee: number;
};
```

쿠폰의 상태와 할인액은 쿠폰 데이터와 계산에 필요한 금액만으로 결정됩니다. 메서드가 있는 클래스를 만들지 않고 순수 함수로 작성해도 엔티티의 규칙을 표현할 수 있습니다.

```ts
type CouponStatus = 'upcoming' | 'available' | 'used' | 'expired';

function getCouponStatus(coupon: Coupon, now: number): CouponStatus {
  // 사용한 쿠폰은 기간이 남아도 다시 사용할 수 없습니다.
  if (coupon.usedAt !== null) return 'used';
  if (now < coupon.validFrom) return 'upcoming';
  // 만료 시각부터는 사용할 수 없습니다.
  if (now >= coupon.expiresAt) return 'expired';
  return 'available';
}

type CouponDiscount = { product: number; shipping: number };

type CouponDiscountResult =
  | { canApply: true; discount: CouponDiscount }
  | {
      canApply: false;
      discount: { product: 0; shipping: 0 };
      reason: 'unavailable' | 'minimum';
    };

function getCouponDiscount(
  coupon: Coupon,
  context: DiscountContext,
  now: number,
): CouponDiscountResult {
  if (getCouponStatus(coupon, now) !== 'available') {
    return {
      canApply: false,
      discount: { product: 0, shipping: 0 },
      reason: 'unavailable',
    };
  }
  // 쿠폰이 유효해도 현재 상품 금액이 사용 조건에 못 미칠 수 있습니다.
  if (context.productTotal < coupon.minimumProductTotal) {
    return {
      canApply: false,
      discount: { product: 0, shipping: 0 },
      reason: 'minimum',
    };
  }

  switch (coupon.benefit.type) {
    case 'amount':
      return {
        canApply: true,
        discount: {
          // 5천 원 할인 쿠폰이어도 상품 가격보다 많이 할인하지 않습니다.
          product: Math.min(coupon.benefit.amount, context.productTotal),
          shipping: 0,
        },
      };
    case 'percent':
      return {
        canApply: true,
        discount: {
          // 상품 금액에 할인율을 적용하고 최대 할인액을 지킵니다.
          product: Math.min(
            Math.floor((context.productTotal * coupon.benefit.rate) / 100),
            coupon.benefit.maxDiscount,
            context.productTotal,
          ),
          shipping: 0,
        },
      };
    case 'shipping':
      return {
        canApply: true,
        // 배송비 할인은 상품 금액에서 빼지 않습니다.
        discount: { product: 0, shipping: context.shippingFee },
      };
  }
}
```

상품 금액이 3만 원이고 배송비가 3천 원이면 5천 원 할인 쿠폰은 상품 금액에서 5천 원을, 배송비 쿠폰은 배송비에서 3천 원을 할인합니다. 10% 할인 쿠폰의 계산값은 3천 원이지만 최대 할인액이 2천 원이면 2천 원만 반환합니다. 상품과 배송비 할인액을 따로 돌려주는 것은 뒤에서 상품 카드의 가격을 계산할 때 필요합니다.

`available`은 쿠폰을 아직 쓰지 않았고 사용 기간 안에 있다는 뜻입니다. 주문 금액 조건은 별개입니다. 상품 금액이 2만 원 이상이어야 하는 쿠폰이라면, 1만 8천 원짜리 주문에는 `getCouponDiscount`가 적용 불가를 반환합니다.

## 쿠폰함을 불러오는 유스케이스

쿠폰함을 열면 고객의 쿠폰과 현재 주문을 백엔드에서 가져옵니다. 각 쿠폰의 상태와 예상 할인액을 계산해 화면에 돌려주는 일은 `loadCouponWallet`이 맡습니다. API 응답을 쿠폰 엔티티로 바꾸는 코드는 통신 쪽에 둡니다.

백엔드가 날짜를 ISO 문자열로 보낸다면, API 구현에서 계산에 쓸 밀리초 값으로 변환합니다.

```ts
type CouponDto = {
  id: string;
  validFrom: string;
  expiresAt: string;
  usedAt: string | null;
  minimumProductTotal: number;
  benefit: CouponBenefit;
};

function toCoupon(dto: CouponDto): Coupon {
  return {
    id: dto.id,
    // API의 날짜 문자열을 계산에 사용할 밀리초 값으로 바꿉니다.
    validFrom: Date.parse(dto.validFrom),
    expiresAt: Date.parse(dto.expiresAt),
    usedAt: dto.usedAt === null ? null : Date.parse(dto.usedAt),
    minimumProductTotal: dto.minimumProductTotal,
    benefit: dto.benefit,
  };
}
```

`loadCouponWallet`은 `fetch` 대신 `CouponApi`와 `OrderApi`를 받습니다. URL이나 헤더가 바뀌어도 이 함수의 계산 과정은 그대로입니다.

```ts
type CouponApi = {
  listMine(): Promise<Coupon[]>;
  applyToOrder(
    orderId: string,
    couponId: string,
  ): Promise<
    { ok: true; quote: OrderQuote } | { ok: false; reason: 'coupon-changed' }
  >;
};

type OrderApi = {
  getCurrent(): Promise<{ id: string } & DiscountContext>;
};

async function loadCouponWallet(deps: {
  coupons: CouponApi;
  orders: OrderApi;
  now: () => number;
}) {
  const [coupons, order] = await Promise.all([
    deps.coupons.listMine(),
    deps.orders.getCurrent(),
  ]);
  // 목록 전체를 같은 시각으로 평가해 만료 경계의 결과를 맞춥니다.
  const now = deps.now();

  return {
    orderId: order.id,
    coupons: coupons.map((coupon) => ({
      id: coupon.id,
      status: getCouponStatus(coupon, now),
      preview: getCouponDiscount(coupon, order, now),
    })),
  };
}
```

예를 들어 쿠폰함에 만료일 순 정렬을 추가한다면 `loadCouponWallet`이 만든 목록을 정렬하면 됩니다. 만료 시각의 포함 여부가 바뀌는 경우에는 `getCouponStatus`를 고쳐야 쿠폰함과 뒤에 나올 상품 카드가 같은 결과를 냅니다.

실제 HTTP 요청은 `CouponApi` 구현에 둡니다. 서버가 쿠폰 적용을 거절한 `409` 응답은 쿠폰 상태가 바뀌었다는 결과로 변환합니다.

```ts
const couponApi: CouponApi = {
  async listMine() {
    const response = await fetch('/api/me/coupons');
    if (!response.ok) throw new Error('COUPON_LIST_FAILED');
    const dtos = (await response.json()) as CouponDto[];
    // 유스케이스에는 API 응답 형식 대신 쿠폰 엔티티를 전달합니다.
    return dtos.map(toCoupon);
  },
  async applyToOrder(orderId, couponId) {
    const response = await fetch(`/api/orders/${orderId}/coupon`, {
      method: 'PUT',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify({ couponId }),
    });
    // 쿠폰 상태가 바뀐 응답은 목록을 다시 읽을 수 있는 결과로 변환합니다.
    if (response.status === 409) {
      return { ok: false, reason: 'coupon-changed' };
    }
    if (!response.ok) throw new Error('COUPON_APPLY_FAILED');
    return { ok: true, quote: await response.json() };
  },
};

const orderApi: OrderApi = {
  async getCurrent() {
    const response = await fetch('/api/orders/current');
    if (!response.ok) throw new Error('ORDER_LOAD_FAILED');
    return response.json();
  },
};
```

## 쿠폰 적용 요청과 서버 응답

사용자가 쿠폰을 선택하면 `applyCouponToOrder`가 백엔드에 적용을 요청합니다. 쿠폰함에서 미리 계산한 할인액은 화면에 보여줄 값이며, **주문 금액은 서버 응답으로 확정합니다**.

```ts
type OrderQuote = {
  discount: number;
  payable: number;
};

async function applyCouponToOrder(
  input: { orderId: string; couponId: string },
  deps: { coupons: CouponApi; orders: OrderApi; now: () => number },
) {
  const result = await deps.coupons.applyToOrder(input.orderId, input.couponId);
  if (result.ok) return result;

  // 서버가 쿠폰 상태 변경을 알리면 화면에 줄 목록을 다시 만듭니다.
  const wallet = await loadCouponWallet(deps);
  return { ok: false as const, reason: result.reason, wallet };
}
```

브라우저 시계가 서버와 다르거나 고객이 다른 기기에서 쿠폰을 이미 썼다면, 화면의 예상 할인액과 서버 응답이 달라질 수 있습니다. 이때 `applyCouponToOrder`는 쿠폰함을 다시 불러와 최신 상태를 보여줍니다. 주문을 최종 확정할 때도 백엔드의 쿠폰 검사가 필요합니다.

```tsx
const wallet = await loadCouponWallet({
  coupons: couponApi,
  orders: orderApi,
  now: Date.now,
});
setWallet(wallet);

// 예상 할인액은 화면용이며, 적용 후 금액은 API 응답으로 갱신합니다.
const result = await applyCouponToOrder(
  { orderId: wallet.orderId, couponId: selectedCouponId },
  { coupons: couponApi, orders: orderApi, now: Date.now },
);
if (result.ok) {
  setQuote(result.quote);
} else {
  setWallet(result.wallet);
  setMessage('쿠폰 상태가 변경됐습니다.');
}
```

## 상품 카드의 쿠폰 적용 최저가

이제 상품 카드에도 “보유 쿠폰 적용 시 최저가”를 표시해야 합니다. 로그인한 고객이 상품을 한 개 살 때, 보유 쿠폰 중 상품 금액을 가장 많이 할인하는 쿠폰을 적용한 가격입니다. 쿠폰은 한 장만 사용할 수 있고 배송비는 상품 카드의 가격에 포함하지 않는다고 정합니다.

상품 가격은 3만 원, 배송비는 3천 원이고 고객에게 다음 쿠폰이 있습니다. 모두 사용 기간 안에 있고 아직 쓰지 않았습니다.

| 쿠폰             | 조건                  | 상품에서 할인되는 금액 |
| ---------------- | --------------------- | ---------------------: |
| 5천 원 할인 쿠폰 | 상품 금액 2만 원 이상 |                 5천 원 |
| 10% 할인 쿠폰    | 최대 2천 원 할인      |                 2천 원 |
| 배송비 쿠폰      | 배송비 전액 할인      |                    0원 |

상품 카드에 표시할 가격은 2만 5천 원입니다. 배송비 쿠폰은 결제액을 낮출 수 있어도 **상품 가격을 낮추지는 않습니다**. 같은 쿠폰을 가진 고객이 1만 8천 원짜리 상품을 보면 5천 원 할인 쿠폰은 최소 주문 금액에 못 미치므로, 10% 할인 쿠폰을 적용한 1만 6천 2백 원이 표시됩니다.

상품 카드 컴포넌트에서 할인액을 다시 계산하면 쿠폰함에 썼던 만료일·최소 주문 금액·최대 할인액 조건이 복사됩니다. 배송비 쿠폰도 같은 방식으로 상품 가격에서 빼 버리면 카드에는 2만 7천 원이 표시됩니다. 실제 배송비 쿠폰의 적용 결과는 상품 3만 원에 배송비 0원입니다. 카드의 2만 7천 원 표시는 잘못됐습니다.

### 상품과 쿠폰을 조합하는 위치

상품 모델에는 판매 가격이 있고, 쿠폰 엔티티는 주어진 금액의 할인액을 계산합니다. 고객의 쿠폰 중 무엇을 골라 상품 카드에 표시할지는 `getBestCouponPrice`가 결정합니다. 이 함수는 상품과 보유 쿠폰을 각각 조회한 뒤 할인액을 비교합니다. 상품 모델에 고객의 쿠폰 목록이나 쿠폰 선택 메서드를 넣을 이유는 없습니다.

```ts
type Product = { id: string; price: number };
type ProductDto = { id: string; sellingPrice: number };

type ProductApi = {
  getById(productId: string): Promise<Product>;
};

async function getBestCouponPrice(
  input: { productId: string },
  deps: {
    products: ProductApi;
    coupons: Pick<CouponApi, 'listMine'>;
    now: () => number;
  },
) {
  const [product, coupons] = await Promise.all([
    deps.products.getById(input.productId),
    deps.coupons.listMine(),
  ]);
  const now = deps.now();
  let best = { couponId: null as string | null, productDiscount: 0 };

  for (const coupon of coupons) {
    // 상품 한 개의 가격만 비교하므로 배송비는 계산 대상이 아닙니다.
    const result = getCouponDiscount(
      coupon,
      { productTotal: product.price, shippingFee: 0 },
      now,
    );
    if (!result.canApply) continue;

    const productDiscount = result.discount.product;
    // 쿠폰 한 장만 적용하므로 상품 할인액이 가장 큰 후보를 남깁니다.
    if (productDiscount > best.productDiscount) {
      best = { couponId: coupon.id, productDiscount };
    }
  }

  return {
    productId: product.id,
    originalPrice: product.price,
    lowestPrice: product.price - best.productDiscount,
    couponId: best.couponId,
  };
}
```

상품 카드에서 `getCouponDiscount`에 넘기는 값은 상품 하나의 가격과 `0`원인 배송비입니다. 쿠폰함은 진행 중인 주문 금액을 넘깁니다. 두 유스케이스가 같은 쿠폰 규칙을 쓰면서도 서로를 호출하지 않는 이유입니다. 상품 카드에서 쿠폰함 조회 유스케이스를 재사용하면 필요하지 않은 현재 주문까지 가져오게 됩니다.

상품 API 응답의 `sellingPrice`는 통신 코드에서 `Product`의 `price`로 바꿉니다.

```ts
const productApi: ProductApi = {
  async getById(productId) {
    const response = await fetch(
      `/api/products/${encodeURIComponent(productId)}`,
    );
    if (!response.ok) throw new Error('PRODUCT_LOAD_FAILED');
    const dto = (await response.json()) as ProductDto;
    return { id: dto.id, price: dto.sellingPrice };
  },
};
```

쿠폰 두 장을 함께 쓸 수 있게 된다면 `getBestCouponPrice`의 선택 방식을 고쳐야 합니다. 쿠폰 한 장의 유효기간과 할인액 계산은 그대로 쓸 수 있습니다. 다만 상품 카드의 가격은 상품 한 개를 산다는 전제로 계산했습니다. 장바구니에 다른 상품을 담아 최소 주문 금액을 채우면 실제로 사용할 수 있는 쿠폰이 달라질 수 있으므로, 주문 화면은 백엔드가 반환한 금액을 사용합니다.

## 요구사항별 수정 지점

상품 카드에 최저가를 표시하면서 새로 필요한 것은 상품 가격과 보유 쿠폰을 가져와 한 장을 고르는 `getBestCouponPrice`입니다. 쿠폰의 만료 조건이나 할인액 계산은 쿠폰함에서 쓰던 함수를 그대로 사용합니다. 이후 10% 할인 쿠폰의 최대 할인액이 바뀌면 `getCouponDiscount`를 고쳐 두 화면에 반영할 수 있습니다.

처음에는 한 함수로 충분했던 쿠폰 기능이 상품 카드까지 이어졌습니다. 쿠폰 한 장의 조건은 엔티티에 두고, 쿠폰함과 상품 카드가 각각 필요한 데이터를 모으는 일은 유스케이스에 두면 조건을 화면마다 복사하지 않아도 됩니다.
