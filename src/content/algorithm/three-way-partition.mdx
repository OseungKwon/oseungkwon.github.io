## 언제 쓰나

배열에 들어 있는 값이 **세 종류뿐**이고, 그 순서대로 모아야 할 때 씁니다.

- 0·1·2, 빨강·하양·파랑처럼 값의 종류가 셋으로 정해져 있습니다.
- 값 자체가 셋이 아니어도 "기준값보다 작다 / 같다 / 크다"처럼 세 무리로 나누는 문제라면 같은 방법이 통합니다. 퀵 정렬에서 기준값과 같은 원소가 많을 때 배열을 세 구역으로 나누는 것도 이 방법입니다.
- 새 배열을 만들지 않고 입력 배열 안에서, 배열을 한 번만 훑어서 끝내야 합니다.

## 어떻게 동작하나

### 개수를 세면 두 번 훑는다

LeetCode 75는 0, 1, 2가 섞인 배열을 라이브러리 정렬 함수 없이 0, 1, 2 순서로 정렬하는 문제입니다. `nums = [2, 0, 2, 1, 1, 0]`이면 `[0, 0, 1, 1, 2, 2]`가 되어야 합니다.

가장 먼저 떠오르는 방법은 개수를 세는 것입니다. 한 번 훑어 0이 2개, 1이 2개, 2가 2개라는 것을 센 뒤, 한 번 더 훑으며 앞에서부터 0을 두 칸, 1을 두 칸, 2를 두 칸 적으면 됩니다. 이 방법도 O(n)이지만 배열을 두 번 훑습니다. 문제의 후속 질문은 **한 번만 훑고** 추가 공간은 변수 몇 개만 쓰는 방법을 묻는데, 그 답이 이 글의 세 구역 분할입니다.

### 네 구역으로 나눠 두고 가운데를 줄인다

한 번만 훑으려면 값을 읽는 즉시 제자리 근처로 보내야 합니다. 그래서 배열을 네 구역으로 나눠 두고, 포인터 세 개로 구역의 경계를 표시합니다. 아래는 정렬하는 도중의 한 장면입니다.

<SortColorsRegions nums={[0, 1, 1, 2, 0, 1, 2, 2]} lo={1} mid={3} hi={5} />

그림은 이렇게 읽습니다.

- 칸 위의 `lo`, `mid`, `hi`는 세 포인터가 각각 가리키는 칸입니다. 포인터는 배열의 칸 번호를 담은 변수입니다.
- 칸 아래의 괄호가 네 구역입니다. `lo` 앞은 **0 구역**, `lo`부터 `mid` 앞까지는 **1 구역**, `mid`부터 `hi`까지는 **안 본 칸**, `hi` 뒤는 **2 구역**입니다.
- 0 구역과 2 구역의 칸은 자리가 정해졌으니 다시 볼 필요가 없습니다. 노란 칸이 `mid`가 지금 읽는 칸입니다.

알고리즘은 안 본 칸의 맨 앞, 즉 `mid` 칸의 값을 읽고 그 값에 맞는 구역으로 보냅니다.

1. **0이면** `lo` 칸과 값을 바꾸고 `lo`와 `mid`를 함께 한 칸 오른쪽으로 옮깁니다. 0 구역이 한 칸 늘어납니다.
2. **1이면** 그대로 두고 `mid`만 한 칸 오른쪽으로 옮깁니다. 1 구역이 한 칸 늘어납니다.
3. **2이면** `hi` 칸과 값을 바꾸고 `hi`만 한 칸 왼쪽으로 옮깁니다. 2 구역이 한 칸 늘어나고, `mid`는 그대로 둡니다.

어느 경우든 안 본 칸이 한 칸씩 줄어들고, `mid`가 `hi`를 지나쳐 안 본 칸이 없어지면 배열은 0 구역, 1 구역, 2 구역 순서로 정렬된 상태입니다. 이 문제는 에츠허르 데이크스트라(Edsger Dijkstra)가 네덜란드 국기의 세 색에 빗대어 낸 문제라 **네덜란드 국기 문제**(Dutch national flag problem)라고도 부릅니다.

### 왜 2와 바꿀 때만 mid가 멈추나

세 규칙 중 3번만 `mid`를 옮기지 않는 이유는 바꿔 온 값이 어디서 왔는지에 있습니다.

0을 `lo` 칸과 바꾸면 `mid` 칸으로 오는 값은 `lo` 칸에 있던 값입니다. `lo` 칸은 1 구역의 첫 칸이라 그 값은 이미 읽은 1이고, `lo`와 `mid`가 같은 칸이면 제자리 교환이라 값이 바뀌지 않습니다. 어느 쪽이든 `mid` 칸에는 이미 확인한 값이 남으므로 `mid`를 옮겨도 됩니다.

반면 2를 `hi` 칸과 바꾸면 `mid` 칸으로 오는 값은 안 본 칸의 맨 끝에서 온, 아직 읽지 않은 값입니다. 0일 수도 있고 2일 수도 있으니, `mid`는 그 자리에 남아 다음 반복에서 이 값을 다시 읽어야 합니다.

### 직접 따라가 보기

아래에서 "다음"을 누르면 `mid`가 한 칸을 읽을 때마다 포인터와 구역 괄호가 함께 움직입니다. 2번째 단계에서 맨 앞의 2가 맨 뒤의 0과 교환 후보로 이어지고, 3번째 단계에서 두 값이 바뀝니다. 이때 `hi`만 왼쪽으로 한 칸 오고 `mid`는 맨 앞에 그대로 남는 것을 보세요. 4번째 단계에서 `mid`가 그 자리로 온 0을 읽고 나서야 0 구역이 생깁니다. 6~7번째 단계에서도 같은 장면이 한 번 더 나옵니다.

## 대표 문제 풀이

아래는 참고 풀이입니다. 반복문 안의 ①②③이 위의 세 규칙과 같은 순서이고, 변수 이름은 시각화의 변수 칸과 같습니다.

```js
function sortColors(nums) {
  let lo = 0;
  let mid = 0;
  let hi = nums.length - 1;

  while (mid <= hi) {
    if (nums[mid] === 0) {
      // ① 0은 앞으로: lo 칸과 바꾸고 둘 다 오른쪽으로
      [nums[lo], nums[mid]] = [nums[mid], nums[lo]];
      lo++;
      mid++;
    } else if (nums[mid] === 1) {
      // ② 1은 그대로: mid만 오른쪽으로
      mid++;
    } else {
      // ③ 2는 뒤로: hi 칸과 바꾸고 hi만 왼쪽으로. mid는 그대로
      [nums[mid], nums[hi]] = [nums[hi], nums[mid]];
      hi--;
    }
  }
}
```

반복 조건이 `mid <= hi`인 것은 `mid`와 `hi`가 같은 칸일 때도 안 본 칸이 하나 남아 있기 때문입니다. 반복 한 번마다 `mid`가 오른쪽으로 가거나 `hi`가 왼쪽으로 와서 안 본 칸이 한 칸씩 줄어드니, 반복은 최대 n번이고 시간은 O(n)입니다. 입력 배열 안에서 값만 바꾸고 변수 세 개만 더 쓰므로 공간은 O(1)입니다.

## 자주 하는 실수

**2를 `hi` 칸과 바꾼 뒤에도 `mid`를 옮깁니다.** 세 경우 모두 `mid++`를 넣으면 코드 모양은 더 고르지만, `hi` 칸에서 온 값을 읽지 않고 지나치게 됩니다. `[1, 2, 0]`에서는 2와 맨 뒤의 0을 바꾼 뒤 `mid`가 그 0을 건너뛰어, 0이 1 구역에 남은 채 반복이 끝납니다.

<SortColorsSkip nums={[1, 2, 0]} caption="바뀐 0을 읽지 않고 mid가 지나가, 결과가 [1, 0, 2]로 끝납니다." />

이 실수는 LeetCode 75의 예제 1·2에서는 우연히 맞는 답을 내므로, 예제만 돌려 보고는 알아차리기 어렵습니다. `[1, 2, 0]`처럼 2 뒤에서 0이 넘어오는 입력으로 한 번 더 확인하면 드러납니다.

**반복 조건을 `mid < hi`로 씁니다.** `mid`와 `hi`가 같은 칸을 가리킬 때 그 칸은 아직 읽지 않은 칸인데, 조건이 `<`이면 이 칸을 읽지 않고 끝납니다. 예제 2의 `[2, 0, 1]`을 넣으면 `[1, 0, 2]`가 나옵니다.
